# Chaldea 羁绊补齐自动编队测试验证清单

## 1. 文档用途

本文档用于持续记录「Chaldea 自动补齐从者和羁绊礼装」的待测场景、实机结果、
失败现场与回归结论。功能逻辑发生变化、实机暴露新问题或完成一轮验证后，应直接更新
本文档；不要另外创建带日期的重复测试清单。

设计与业务规则见
[`Chaldea羁绊补齐自动编队方案.md`](Chaldea羁绊补齐自动编队方案.md)。

状态约定：

- `待验证`：尚无足够证据。
- `部分通过`：离线或局部分支通过，但未完成端到端实机验证。
- `通过`：已在真实游戏界面覆盖预期分支，并取得截图或关键日志。
- `失败`：实际结果不符合预期，必须记录问题和故障现场。
- `阻塞`：当前账号、队伍或库存无法构造该场景。

## 3. 每轮实机测试的固定流程

### 3.1 测试前

1. 记录使用的 Chaldea 队伍 ID、补齐选项、羁绊基础值和预期星级顺序。
2. 截图并记录原队伍六个槽位、助战位置、已有礼装及 `used/max COST`。
3. 明确本轮要覆盖的测试编号，不为顺带提高覆盖率而擅自更改玩家领取、强化或库存。
4. 确定安全恢复方案；恢复只能还原本轮测试造成的编队修改，不改动其他队伍和资源。

### 3.2 运行中

1. 记录关键节点：进入配置页、首次 COST、每个星级首屏、每次最终选人、每次装卸礼装、
   最终决定及二次确认弹窗。
2. 识别失败、超时、误点击、进入意外页面或命中错误恢复分支时，立即把它当作“现场
   断点”：先暂停会继续点击、后退或返回主界面的流程，再截图和检查识图详情。
3. 识图故障至少保留：完整截图、实际 ROI、模板、最高分、阈值、第二候选分数、候选框/
   点击坐标、最后成功节点及异常节点日志。不得只查看已经返回主界面后的最终截图。
4. 调整 ROI、裁剪或阈值时，使用故障帧离线复现，并与同屏全部候选比较；不能只验证
   目标模板自己的得分。

### 3.3 测试后

1. 重新识别五名本地从者和所有本地礼装，确认助战及其礼装从未被编辑或计分。
2. 读取最终 COST，确认 `used <= max`；重新计算实际羁绊值并与日志计划值比较。
3. 检查 Chaldea 指定槽位和原有礼装均未被覆盖。
4. 恢复测试前队伍并截图复核。仅在现场材料已保存后执行失败恢复。
5. 更新本文档对应测试项的状态、日期、队伍 ID、结果和证据位置。

## 4. P0：交付前优先验证

### P0-01 当前头像裁剪与高阈值全流程回归

- 状态：`待验证`
- 前置：加载包含内存裁剪 `(44, 44, 158, 101)`、阈值 `0.88` 和分差 `0.12` 的当前代码。
- 操作：选择至少含两个可补从者位的队伍，完成“完整扫描 → 规划 → 回顶部重新定位 →
  点击目标 → 编队复核”。
- 预期：所有最终目标均正确；不得因高阈值漏掉真实目标，也不得选择同屏次优头像。
- 必留证据：每名最终目标的最高/次高分、选中前截图、返回编队页后的槽位复核截图。

### P0-02 从者 COST 超限后的候选降级

- 状态：`待验证`
- 前置：构造剩余 COST 放不下当前最优高星从者、但能放下更低 COST 从者的队伍。
- 操作：优先星级设为 5 星，运行至首次候选被 COST 拒绝。
- 预期：先尝试已扫描集合中的低 COST 候选；当前星级都放不下时，按既定星级队列继续，
  不得直接结束、超 COST 点击或改动受保护槽位。
- 必留证据：初始 COST、被拒绝对象与估算 COST、降级顺序、每次选择后的实际 COST。

### P0-03 礼装 COST 超限与卸载回退

- 状态：`待验证`
- 前置：队伍剩余 COST 只允许装入部分计划礼装。
- 操作：让礼装阶段出现实测 COST 不足，覆盖“换低 COST 礼装”和“仍不足则卸下”的路径。
- 预期：只允许卸下本功能本轮新增、边际收益最低的礼装；Chaldea 指定礼装和运行前已有
  礼装必须保持原位。
- 必留证据：每张候选的收益/COST、装入前后 UI COST、卸载对象和最终槽位截图。

### P0-04 优先星级无人时切换下一星级

- 状态：`待验证`
- 前置：选择一个账号当前没有匹配对象的优先星级，且下一优先级至少有一名可用从者。
- 操作：完成当前星级最多 15 次下滑或提前到底，再进入下一星级。
- 预期：执行“当前星级扫描结束 → 回顶部 → 重新筛选 → 新星级首屏识别 → 下滑”；
  新星级首屏不能漏扫，旧星级候选不能残留。
- 必留证据：两次星级筛选截图、各自首屏命中数、切换日志和最终选择。

### P0-05 异常现场保留机制

- 状态：`待验证`
- 前置：使用测试 override 安全制造一次模板缺失或短超时，不修改正式业务 pipeline。
- 操作：触发错误节点，观察测试流程是否先停留并取证，再运行恢复。
- 预期：返回主界面前已保存错误瞬间截图和识别数据；日志能定位最后成功节点与失败节点。
- 必留证据：故障帧、ROI、模板与最高分、阈值、节点日志、恢复前后截图。

### P0-06 助战和原始槽位保护

- 状态：`部分通过`
- 前置：选择包含助战、Chaldea 指定礼装以及预期空槽中残留旧从者的队伍。
- 操作：同时补从者和礼装，并完成最终复核。
- 预期：助战人物与礼装不编辑、不计分；指定本地从者/礼装不被覆盖；仅允许替换 Chaldea
  预期为空且实现规则允许处理的残留槽位。
- 已有证据：正常主流程中助战保持不变；组合边界尚未一次性完整覆盖。

## 5. P1：识别与组合边界

| 编号 | 场景 | 验证重点 | 状态 |

| P1-01 | 1～4 星分别扫描 | 新裁剪和 `0.88` 阈值不能只在 5 星成立；每个星级至少覆盖顶部、中部、底部头像。 | 待验证 |
| P1-02 | 相似头像与不同灵基 | 同一从者不同灵基、同脸角色或相近色调同时出现时，目标须过阈值且领先第二名 `0.12`；否则安全拒绝。 | 待验证 |

| P1-04 | 顶部竞态 | 首次零命中时二次回顶能恢复；若仍为零，保留现场后停止/继续星级回退，不应先滑走。 | 部分通过 |

| P1-09 | 相似工坊/羁绊礼装 | 多张构图相近礼装同屏时，确认 list 模板不会误选，并以 team 模板复核。 | 待验证 |
| P1-10 | 已满五名本地从者 | 不进入从者仓库，只处理允许的空礼装位。 | 待验证 |
| P1-11 | 礼装自动编队关闭 | 原流程视为礼装阶段完成；补齐仍运行，但不得覆盖 Chaldea 明确指定的礼装。 | 待验证 |
| P1-12 | 保存/人数不足弹窗 | 修改后返回的“是否保存队伍”和点击决定后的“人数不足”弹窗均只能点击正确按钮一次。 | 部分通过 |
| P1-13 | COST OCR 异常 | 空文本、非 `XX/XXX`、两帧不一致或 `used > max` 时安全停止，不使用估算值提交。 | 待验证 |

| --- | --- | --- | --- |
| P2-01 | 多队伍重复运行 | 至少选择 3～5 个从者数量、助战位置、已有礼装不同的 Chaldea 队伍，确认没有状态残留。 | 待验证 |

## 7. 单次测试记录模板

完成测试后，在对应测试项下追加记录；同一测试的旧失败记录应保留，以便确认回归原因。

```markdown
#### YYYY-MM-DD / 测试编号

- 状态：通过 / 失败 / 部分通过 / 阻塞
- Chaldea 队伍 ID：
- 测试配置：优先星级、bond_base、相关开关
- 初始状态：本地从者、助战、礼装、COST
- 关键结果：命中对象、分数、阈值、滑动次数、COST、羁绊增量
- 故障现场：截图/日志路径；没有故障则写“无”
- 最终状态：保护槽、助战、COST、羁绊复核
- 恢复结果：
- 后续动作：无需处理 / 修复并复测 / 需要补充测试条件
```

## 8. 更新规则

- 修复代码不自动把测试项改为“通过”；必须有修复后证据。
- 离线模板匹配不能替代完整实机流程，只能记为“部分通过”。
- 新发现的问题先追加到最贴近的测试项；若属于独立风险，再新增编号，避免用笼统备注覆盖。
- 调整阈值、裁剪、ROI、滑动距离、次数上限或错误恢复路径时，至少回归 P0-01、P0-05
  及直接受影响的测试项。
- 测试截图和临时 override 不作为正式业务资源提交；需要长期保留的证据应使用稳定命名并在
  本文档记录路径。
- 测试中若出现未覆盖的新异常，优先保存现场、记录复现条件，再决定是否继续；不得为了
  完成清单而绕过保护规则。
