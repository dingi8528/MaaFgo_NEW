# 原生战斗合成卡面识别

## 识别入口

`agent/battle/perception/perception.py` 默认调用 `ComposedCardRecognizer`，使用现有 `CommandCardComposer` 合成当前前排从者的指令卡和宝具卡，再与实际选卡截图比较。没有调用编辑器服务或网络。

- 搜索仅限当前前排身份、资源清单登记的立绘和宝具文字，不遍历全部从者。
- 普通卡同时比较三种颜色，允许技能改变卡色。
- 宝具文字与立绘分别枚举，兼容解锁后的宝具名称继续用于原有立绘。
- JP、CN 文字各用本地区资源。缺少某地区素材时，不把另一地区素材冒充为它。
- 合成模板遮罩排除顶部强化图标、暴击率、助战标记、底部 HUD，以及宝具封印横幅所在区域。封印、无法行动仍由独立识别节点判定。

## 不确定性与回退

完整宝具候选存在、但没有匹配到实际卡面时，结果可以明确表示“宝具卡未出现”。此时不能再被背景 `TARGET` 字样、OCR 裁切出的 `ET` 或场景边缘判成可释放宝具。

没有前排身份或资源不完整时，保留原有卡色 OCR、宝具文字与边框复核。当前版本没有替换无身份时的通用识别路径。OCR 失败的普通卡使用 `CardColor.UNKNOWN`，不再默认当红卡；未知卡不会组成假同色链或三色链，但在没有足够已知普通卡时仍可按槽位补齐三张。

同一身份出现在两个前排位置时，普通卡归属不强猜位置；宝具可按上方物理槽位确定位置。宝具是否可用取自实际卡面和封印状态，不根据 NP 条或计划预测。

## 执行边界

合成识别不修改用户的卡牌顺序。缺失的指定普通卡或不可用宝具仍沿原策略补普通卡。没有配置回合时从开始使用通用战斗策略；显式空攻击回合只出普通卡；计划结束后恢复通用策略。

三次出卡点击后持续超过三秒、至少两次观察仍停留在选卡页面时，返回 `card_selection_not_submitted` 并保留现场，不盲目重试或补卡。正常动画处于未知场景时仍保留完整动画等待上限。

## 资源与缓存

生产识别只依赖 `CommandCards/manifest`、`CommandCards/_composition/manifest` 及清单登记的图片。`battle_editor/data/np_cards.json` 仅作为可选变身映射，不要求存在编辑器 Python 包。桌面与安卓均可使用随包的 CommandCards 资源。

合成和缩放模板按候选身份缓存，均有数量和内存上限。资源更新后重启 Agent，或调用 `clear_cache()`；不逐帧扫描文件和重新合成。

## 回归方法

运行 `python tests/test_composed_card_recognition.py` 和 `python tests/test_battle_composed_perception.py`，覆盖缺资源、未知身份、重复身份、JP/CN、缩放、名称变化、卡色变化、封印遮罩、背景负例及缓存边界。`test_battle_np_target_label.py`、`test_battle_card_color.py`、`test_battle_card_submission.py` 分别覆盖旧路径误识别和执行保护。
