# 自动推主线：设计与实施记录

## 目标与范围

从当前主线地图或已打开的副本列表开始，连续推进普通主线战斗和可跳过的纯剧情关卡。新增独立调度入口，不进入通用战斗调度，不回迦勒底主界面，不使用连续出击刷同一关。

每轮优先级固定为：**副本列表已打开 → 当前地图可见 NEXT → 确认地图后轮巡寻找 NEXT**。点击地图节点后必须确认列表打开；每关结束后重新判断位置。

普通助战、NPC 助战、编队、原生战斗和 BBC 单场执行复用工程已有实现。特殊章节解谜、大奥、选项分支、锁定关卡、跨章节导航不在首版自动处理范围；无法继续时说明原因并停止，不把“找不到目标”当成“主线已完成”。

## BBC 核对结果

只读分析本地已提取的 `FGObattle.pyc`，单独反编译 `dealMainStory` 和 `gotoNextOne`，未运行 BBC 程序。

- `dealMainStory` 使用 NEXT 原图与二值遮罩；地图匹配支持 0.4～2.3 的尺度范围、步长 0.05。
- `gotoNextOne` 使用彩色 `TM_SQDIFF_NORMED`，差异阈值 0.2；先寻找地图 NEXT，再确认关卡区域，随后在副本列表再次寻找 NEXT。
- 地图点击在匹配中心下方，1920 基准偏移 150，并随地图缩放调整；列表点击偏移 100。实现必须按 1280×720 换算，并验证点击后状态。
- `reddot` 在该初始化中名为 `daaoreddot`，属于大奥处理，普通主线首版不导入。
- 反编译部分复杂分支可能失真；只参考已核实的模板、算法、数值及两阶段识别思路，不照搬异常控制流。

## 结构

1. `assets/tasks/自动推主线.json`：独立任务，默认原生战斗，支持 BBC 单场交接。
2. `assets/options/自动推主线.json`：推进关卡上限、战斗方式；复用原生助战、Chaldea 编队、苹果选项。
3. `assets/resource/base/pipeline/自动推主线.json`：识别节点、必要动作、入口和状态提示。
4. `agent/custom/main_story_action.py`：有界外层循环，管理状态、计数、超时、停止和单场交接。
5. `agent/custom/main_story_recognition.py`：NEXT 遮罩多尺度匹配，返回可点击点和匹配证据；不依赖 BBC 程序运行。

外层使用克隆 Context，局部配置 BBC 单场次数与模式、编队会话及必要出口，不修改通用调度。地图轮巡复用现有蛇形滑动节点的动作，拆开初始化的重复滑动，每滑一次重新识别；不直接调用带活动 OCR 目标的整个轮巡。

## 状态与交接

- **寻找关卡**：副本列表优先；有列表但无 NEXT 时有限次上下翻查，仍无目标才返回地图。本轮已查空的地图点不得无限重进。
- **地图导航**：菜单与地图专用控件确认地图；当前画面先找 NEXT，仅 miss 后遍历。未知画面不滑动。
- **打开列表**：点击 NEXT 对应地图点，限定重试次数，等待正向列表证据。
- **进入关卡**：列表中以 NEXT 选择待推进关卡，禁止退化为“上次执行”或任意第一关。处理 AP、剧情、任务开始提示；区分点击未生效与真正离开列表。
- **单场原生战斗**：每场初始化编队会话、重置有限节点计数；复用 `进本流程` → `原生自动战斗入口`。确认进入战斗后才计为战斗。
- **单场 BBC**：复用 `bbc战斗`，限定 `run_count=1`、普通模式；不给 BBC 主线地图导航权。BBC 返回后由外层确认结算状态。
- **纯剧情**：离开原列表并处理剧情，重新出现地图/列表后计一次推进，不等待不存在的助战，不增加战斗次数。
- **结算**：复用下一步、好友申请关闭、奖励关闭、跳过剧情动作；出现地图/列表就结束本场。识别失败/撤退则停止，禁止用 run_task 成功推断作战胜利。
- **停止**：推进上限、用户停止、AP 无法补充、遍历无目标、战败、未知状态超时；结果分别报告已推进关卡数与完成战斗数。

战后只推进明确识别的下一步、关闭、剧情按钮，不对未知画面持续盲点；遇到缺少模板的奖励画面会超时停下。纯剧情必须观察到可识别剧情并确认返回地图/列表才计数，短暂黑屏后返回原页不算完成。未同步打包版或更改版本号。

### 纯剧情关点击后的弹窗核对（2026-09-27）

现有通用进本把弹窗分开处理：`进本-点击任务开始` 匹配 `dungeon_enter.png`；`进本-编队提示-点击开始` 匹配 `开始.png`；`进本-关闭告知弹窗` 匹配 `close_botton.png`；进入剧情后，`跳过剧情-点击跳过` 用右上角 OCR 点击跳过，并由 `跳过剧情-确认跳过` 匹配 `battle/是.png` 完成二次确认。普通进本链在关卡点击后依次尝试这些入口。

自动推主线的 `enter()` 没有调用通用“点击关卡”链，而是在已明确选中列表 NEXT 后逐帧调用这些识别节点。对进本弹窗，先尝试 `主线-纯剧情任务开始`，再尝试编队“开始”、普通“任务开始”和告知关闭；剧情跳过仍优先于进本弹窗。每次只有识别命中才点击，不因弹窗出现就计为通关。剧情跳过改为逐帧点击现有 `跳过剧情-点击跳过` 和 `跳过剧情-确认跳过` 两个节点：点跳过后最多等待 4 秒识别确认框，点“是”后留 4 秒供页面切换，再允许下一次跳过；避免嵌套通用跳过链在页面切换中重复触发。剧情已出现后若识别到 `主线-任务完成报酬`，也复用既有结算点击节点，最终仍须连续两帧确认返回地图或列表才计数。

国服现场看到的无战斗弹窗显示“该任务没有战斗／是否开始任务？”，右下按钮为“任务开始”。现有国服 `dungeon_enter.png` 在该按钮上最高仅约 0.398，编队 `开始.png` 约 0.794，均低于各自 0.8 阈值，因此文字相同不代表模板能够复用。新增 `cn/image/main_story/story_start.png`，由国服资源层覆盖 `主线-纯剧情任务开始` 的图片；基础资源仍沿用 `dungeon_enter.png`，供日服沿用现有模板，日服无新剧情可供实机验证。新节点只搜索右下 `[700,520,300,90]` 区域，阈值 0.85，命中后点击匹配框。国服现场 MaaFramework 命中分数为 1.000，点击后确实进入剧情。

现场画面来自国服活动的纯剧情关，并非主线章节。重新从“屯所”地图节点进入，右侧列表 NEXT 成功打开此确认弹窗；自动流程命中“任务开始” 1.000、跳过确认“是”约 0.963，但连续调用通用跳过链时再次停留在剧情画面，155 秒保护停止（`25_reopened_before.png`、`26_event_open_after.png`、`28_event_select_after.png`、`29_story_reopen_run_report.json`）。单步复核中，点剧情画面可推进台词；重新单独点击“跳过”，`32_skip_confirm_capture_after.png` 显示确认框，单独点击“是”后出现“任务完成／获得报酬”（`33_confirm_yes_report.json`、`34_after_yes_wait.png`），随后自动返回活动关卡列表（`35_reward_diagnose_before.png`）。所以这关不是连续两段剧情；弹窗、跳过确认和实际完成均已分别验证，但修改后的逐帧自动跳过尚无可重玩的同关现场来验证整链。活动列表可以被当前列表识别器识别，并不能代表实际主线章节也已覆盖。所有证据存于 `.workbuddy/runtime/maa-mcp-data/evidence/main_story/`。

### 两段剧情后进入战斗的现场（2026-09-27）

用户随后打开国服活动第三话“被神选中的人”（AP 5）。它在第一段剧情跳过后播放一段小动画，再进入第二段剧情，必须再次跳过。MaaMCP 从当前副本列表运行自动推主线的 `locate()` 与 `enter()`：两次 `跳过剧情-点击跳过` 均由右上 OCR 命中，两次 `跳过剧情-确认跳过` 模板得分分别为 0.9630、0.9629；最终 `主线-助战界面` 得分 0.8847，`enter()` 返回 `battle`，截图停在助战选择页（`36_two_story_entry.png`、`37_two_story_enter_report.json`、`37_two_story_enter_after.png`）。因此当前逐帧跳过逻辑已实际覆盖“两段剧情 + 中间动画 + 战斗交接”，并新增对应状态机测试。

继续调用现有单场战斗入口时，进本流程在助战/编队环节触发自动编队快照采集失败和回退，之后三分钟无新节点。停止保护和截图确认仍在助战选择页、尚未开战（`38_two_story_battle_stderr.log`、`39_battle_stop_current.png`）。这属于后续进本/编队交接问题，不影响上述两次剧情跳过结论；本次未验证战斗与结算。停止后已清理 MaaMCP/Agent 进程，未留下持续运行的任务。

后续逐步复现查明原因：`进本-选择助战` 点击后已经到达“队伍确认”页，但前景弹出“编制限制：请将河上彦斋设置为首发队员”。原通用进本把该弹窗按 `进本-关闭告知弹窗` 关闭；其后方的“战斗开始”按钮仍可被 `进本-队伍确认` 以 0.897855 命中，导致进入编队快照采集，而采集程序检测到前景弹窗，报 `not_on_formation_confirmation`。这不是剧情跳过失败，也不是单纯快照算法失效。截图 `42_support_select_after.png` 保留了限制弹窗；`45_restriction_diagnose_report.json` 记录了弹窗标题 OCR 0.99959 与后景按钮误命中。

为避免影响通用进本，自动推主线的原生战斗模式现在先按当前助战选项调用既有助战节点（首个助战、自定义助战或 Chaldea 配置），确认抵达编队或战斗界面后才调用共享 `进本流程`。如命中 `主线-编制限制`，保留弹窗并明确中断，请用户按画面要求手动调整；不尝试猜测或自动替换受限从者。国服现场 `46_restriction_guard_report.json` 已验证能停在弹窗，三种助战配置的助战→编队→共享进本链由单元测试覆盖；日服该限制标题仅配有文字识别预期，未实机验证。

纯剧情完成返回地图或副本列表时，不再凭连续两帧直接计数，而是在页面稳定至少 3 秒且跳过后的切换窗口已结束后确认完成。这样中间短暂露出地图/列表的两段剧情不会被提早计为一关；一段、两段剧情后分别返回地图或列表的路径均有状态机测试。
