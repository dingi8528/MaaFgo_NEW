# Chaldea 冠位自动编队 MCP 测试方案

## 1. 目标

通过 MaaMCP 在真实游戏界面验证本次冠位适配，覆盖以下行为：

1. Chaldea 数据标记 `grandSvt=true` 时，只匹配从者身份与位置，不检查或修改
   `equip1`、`equip2`、`equip3`。
2. 普通礼装入口同时轮询礼装仓库与 `battle/冠位助战礼装编辑弹窗.png`；命中冠位
   弹窗后只发送一次 ESC/Android Back，并把礼装视为满足。
3. 羁绊最大化在本地冠位从者弹窗的 `[267,218,776,171]` 内识别 0～3 张常驻羁绊
   礼装，纳入基线和去重规划，但不卸下或重配；助战槽始终忽略。
4. 大量从者不匹配触发“编队解散”时，若冠位限制导致 5 秒内未出现二次确认，流程
   记录跳过清空，并继续逐槽换位和替换。

## 2. 测试数据与入口

- Chaldea 队伍：`https://link.chaldea.center/laplace/share?id=78119`。
- 数据预期：槽位 1 太公望为冠位助战，槽位 2 女王梅芙为本地冠位从者，槽位 3
  尼莫为普通本地从者。
- 游戏入口：编队确认页或编队编辑页，分辨率为 Maa 目标截图 `1280×720`。
- 仅使用 MaaMCP 发现、连接、截图和运行 pipeline；不使用窗口控制或直接 ADB 操作。

## 3. 用例

### A. 入口与模板确认

1. 发现并连接唯一 ADB 设备。
2. 截图确认当前画面；若不在可安全进入的编队页则停止，请用户调整。
3. 加载正式自动编队、羁绊补齐 pipeline 及必要依赖，确认新增模板和节点可解析。

### B. 冠位礼装弹窗识别

1. 在本地冠位从者礼装位执行一次受控点击。
2. 验证日志命中 `grand` 分支，而非普通礼装选择页。
3. 保存弹窗完整截图和 `[267,218,776,171]` ROI；记录弹窗模板最高分。
4. 验证最多三张常驻羁绊礼装识别结果，并确认一次返回后回到编队编辑页。

### C. Chaldea 冠位槽跳过礼装

1. 使用队伍 78119 运行自动编队测试入口。
2. 验证冠位助战与本地冠位从者只复核从者；日志明确跳过其礼装。
3. 普通从者仍沿用原礼装流程，最终从者布局必须复核通过。

### D. 解散无响应降级

1. 在包含冠位从者且满足“至少一半目标本地从者不匹配”的编队中触发清空优化。
2. 验证“编队解散”点击后 5 秒未出现二次确认。
3. 验证日志出现“跳过解散并改用增量编队”，随后仍能继续识别当前六槽；不得以
   `formation_clear_failed` 直接结束。
4. 清空子流程不得落入 `Global_Null` 或“回主界面”等全局恢复链；返回后必须用编辑页
   模板复核实际页面，避免把离开编队页的恢复结果误报成清空成功。

### E. 羁绊最大化与恢复

1. 运行羁绊分析到冠位礼装读取完成，确认冠位助战未被探测或计分。
2. 确认本地冠位从者识别到的常驻羁绊礼装进入固定礼装集合，冠位槽不进入卸装或
   补装集合。
3. 测试结束若仍在编辑页，通过现有取消配置节点恢复，不点击“编队决定”或“开始任务”。
4. 在 `finally` 中停止 pipeline，并保存最终截图、关键日志和 MCP 清理结果。

### F. 冠位头像仓库定位

1. 使用同时包含普通灵基头像与冠位头像的从者进入小图标仓库列表，并复位到顶部。
2. 分别执行原 `360px` 和缩减 5% 后的 `342px` 下滑，保存两张稳定截图；确认目标卡片
   至少在一张截图中完整显示，且相邻页面保留重叠区域。
3. 使用正式仓库算法离线复现截图：只允许完整卡位参与匹配，冠位目标头像得分应不低于
   `0.88`，并与其他可见卡位保持至少 `0.12` 的分差。
4. 通过自动编队 Action 实际选择该冠位头像，确认点击坐标落在目标卡片、返回编队编辑页，
   且不会误点页面标题或其他灵基头像；测试后取消配置并恢复原队伍。

## 4. 通过标准

- 新增模板与两个关闭弹窗节点均成功加载。
- 冠位弹窗和普通礼装仓库不会互相误判。
- 冠位从者礼装不被普通自动编队复核、卸下或重配。
- 冠位助战礼装完全忽略。
- 解散无响应能稳定降级到增量编队。
- 冠位头像使用仓库卡位特征稳定命中，标题栏和其他从者卡位不会被误选。
- 未发生进入战斗、误选礼装或保存测试编队；测试结束后控制器已停止。

## 5. 2026-09-12 实机结果

测试设备为 `MuMu安卓设备-MuMuPlayer v5+`，入口为 Grand Duel `LIMITED` 编队：
第 1 槽是本地冠位从者，第 3 槽是冠位助战。

- 清空降级：通过。点击“编队编辑”后约 20 秒仍未进入清空流程，任务识别到仍在
  编队确认页，记录 `skipped`，随后“配置变更”模板以 `0.9995/0.80` 命中并进入
  标准编辑页。过程中没有落入 `Global_Null` 或回主界面。
- 助战跳过：通过。六槽识别为 `OTHER, OTHER, SUPPORT, OTHER, OTHER, OTHER`，只探测
  本地槽 `[1, 2, 4, 5, 6]`，第 3 槽冠位助战没有打开礼装入口。
- 冠位弹窗竞速：通过。第 1 槽点击礼装后判定为 `grand`，
  `battle/冠位助战礼装编辑弹窗.png` 匹配分数为 `0.9780/0.80`；单次 ESC/Back 后
  回到编辑页。槽位 2、4、5、6 均判定为普通 `select`，进入和返回礼装仓库正常。
- 弹窗礼装识别：通过。在 `[267,218,776,171]` 内识别到 2 张常驻羁绊礼装：
  `迦勒底午餐时光(9401970)`、`迦勒底之人(9408990)`，符合 0～3 张规则。
- 恢复与清理：通过。测试未更换从者或礼装；使用现有取消节点回到原编队确认页，
  未点击“开始任务”，风暴罐保持 `1/9`，最后调用 `stop_pipeline` 清理 Agent。
